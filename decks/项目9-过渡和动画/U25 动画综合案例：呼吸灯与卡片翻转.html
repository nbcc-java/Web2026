任务 9-4｜制作呼吸灯动画

由交替的圆圈 1、圆圈 2 构成，实现图 9-18 的动画效果

任务目标用两个 50px×50px、颜色为 rgba(250,0,0,0.5) 的圆圈，做出此起彼伏的呼吸感。
  1. 搭结构：一个 .outer 里放两个 .ball（ball1、ball2），均绝对定位到 top:0; left:0。
  2. 画圆：50px×50px + border-radius:50% + background-color:rgba(250,0,0,0.5)。
  3. 定关键帧：ball1 从大到小再回大；ball2 与之完全相反。
  4. 启用动画：animation: bounce1 2s ease-in-out infinite;（ball2 用 bounce2）。
  5. 教材提醒：制作动画要先从动画的构造开始分析，而不是一上来就写代码。
/* 关键帧规则 */
@keyframes bounce1{ 0%,100%{ transform:scale(1.0);} 50%{ transform:scale(0);}}
@keyframes bounce2{ 0%,100%{ transform:scale(0.0);} 50%{ transform:scale(1.0);}}
原理图解

分析方法：先在脑子里建立「时间的影像」

教材教学要点：制作动画时先从动画的构造开始分析

① 拆构造
这个动画由几个元素组成？呼吸灯 = 圆圈 1 + 圆圈 2，两个都是圆，只是「节奏不同」。
② 画单个元素的时间线
圆圈 1：起点最大（图 9-19）→ 中间缩为 0 → 末尾回到最大。写成 0%,100%{scale(1)} 50%{scale(0)}。
③ 画第二个元素的时间线
圆圈 2（图 9-20）：与圆圈 1 完全相反——起点为 0，中间最大，末尾回到 0。
④ 找出两者的关系
把两条时间线并排（图 9-21）会发现：运动规律完全一样，只差一个时间差。这正是优化的突破口。
教材结论：观察到「规律一样、只差时间差」之后，就不需要定义两个动画了。
代码示例

初始实现：两个关键帧（代码 9-7）

能跑，但 bounce1 与 bounce2 的代码高度重复

CSS style.css
/* 代码 9-7 */
.ball{ width:50px; height:50px; border-radius:50%; position:absolute;
       top:0; left:0; background-color:rgba(250,0,0,0.5);}
.ball1{ -webkit-animation:bounce1 2s ease-in-out infinite;
        -o-animation:bounce1 2s ease-in-out infinite;
        animation:bounce1 2s ease-in-out infinite;}
.ball2{ -webkit-animation:bounce2 2s ease-in-out infinite;
        -o-animation:bounce2 2s ease-in-out infinite;
        animation:bounce2 2s ease-in-out infinite;}
.outer{ width:200px; margin:0 auto; position:relative;}
兼容性写法：代码中保留了 -webkit-（Safari / Chrome）与 -o-（Opera）前缀，最后一行才是标准属性——按「先私有、后标准」的顺序书写，是良好的编程习惯。
代码示例

代码优化：只留一个动画（代码 9-8）

用 animation-delay 让第二个圆圈延迟执行，省掉一整套重复的关键帧

CSS style.css
/* 代码 9-8 */
.ball{ width:50px; height:50px; border-radius:50%; position:absolute; top:0; left:0;
       background-color:rgba(250,0,0,0.5);
       -webkit-animation:bounce 2s ease-in-out infinite;
       -o-animation:bounce 2s ease-in-out infinite;
       animation:bounce 2s ease-in-out infinite;}
@keyframes bounce{ 0%,100%{ transform:scale(1.0);} 50%{ transform:scale(0);}}
.ball2{ animation-delay:1s;}
.outer{ width:200px; margin:0 auto; position:relative;}
教材解析：统一定义 bounce 动画后，只需给圆圈 2 加 animation-delay:1s（动画周期为 2s，延迟半个周期即可错开），大大减少了代码重复，优化了整体设计。
知识要点

从「能跑」到「好看」：一次典型的迭代优化

良好的编程习惯（教材原文）

  • 良好的编程习惯（教材原文）：不断思考如何优化产品，是互联网迭代思维的体现，也是工匠精神的体现。
  • 第 1 版：两个关键帧，逻辑直白但重复——先保证「效果对」。
  • 第 2 版：合并为一个关键帧 + animation-delay——保证「代码干净」。
  • animation-delay 也支持负值：写 -1s 表示动画「已经播了 1 秒」的状态，常用于多个元素错落启动。
  • 判断标准：效果一致、代码更少、更易维护，就是一次成功的迭代。

任务 9-5｜制作卡片翻转动画

一个 60px×60px、颜色 #67cf22 的正方形卡片，实现图 9-22 的翻转效果

任务目标制作一个先沿 x 轴翻转、再沿 y 轴翻转的、具有透视效果的 3D 动画。
  1. 搭结构：.wrap 里放一个 .spinner，尺寸 60px×60px，背景 #67cf22。
  2. 关键一步：.spinner 必须写 transform-style:preserve-3d，让它在 3D 空间中呈现。
  3. 定义 @keyframes animPlane：0% 不旋转 → 50% 沿 x 轴转 −180 度 → 100% 再沿 y 轴转 −180 度。
  4. 每一帧都要带上 perspective(120px)——透视距离写在子元素自身上。
  5. 启用动画：animation: animPlane 1.0s infinite ease-in-out;
/* 代码 9-9 */
@keyframes animPlane {
  0%   { transform: perspective(120px) rotateX(0deg) rotateY(0);}
  50%  { transform: perspective(120px) rotateX(-180deg) rotateY(0);}
  100% { transform: perspective(120px) rotateX(-180deg) rotateY(-180deg);}}
.spinner{
    width:60px; height:60px; background-color:#67cf22; margin:100px auto;
    transform-style:preserve-3d;
    animation: animPlane 1.0s infinite ease-in-out;}
对比辨析

perspective 的两种写法，哪个更简洁

教材简述题：把任务 9-5 改成「指定父元素」的方式，比较写法区别

指定子元素（任务 9-5 原写法）
  • 写法：transform: perspective(120px) rotateX(…);——透视函数跟在 transform 里
  • 每一帧的关键帧里都要重复写一遍 perspective()
  • 优点：自包含，元素搬到哪里都自带透视，适合单个独立元素
  • 缺点：关键帧一多就重复冗长，改透视距离要改每一处
指定父元素（改造写法）
  • 写法：父元素写 .wrap{ perspective:120px; }，子元素关键帧只写旋转
  • 改造后：0%{transform:rotateX(0)} 50%{transform:rotateX(-180deg)} …
  • 优点：关键帧干净，一个场景共用同一透视距离，改一处即可
  • 缺点：透视依赖父容器，元素换父级就要重新设置
  • 课堂结论：多元素 3D 场景用「指定父元素」更简洁；单个元素的临时特效用「指定子元素」更方便

交互演示｜呼吸灯 + 卡片翻转组合

知识要点

循环动画与常见错误排查清单

做不出来的时候，按这个顺序逐条检查

  • 动画完全不动：检查 animation-name 是否与 @keyframes 名称完全一致（含大小写）。
  • 只播一次就停：没写 infinite——animation-iteration-count 默认值是 1。
  • 一闪而过没过程：没写时长——animation-duration 默认值是 0。
  • 3D 没有立体感：父级漏了 transform-style:preserve-3d，或关键帧里漏了 perspective()。
  • 多个元素同步得刺眼：用 animation-delay（可正可负）让它们错峰启动。

AI 前沿：让 AI 帮你做那次「迭代」

从代码 9-7 到 9-8 的优化，正是 AI 最擅长的重构

AI

教材里那次从「两个关键帧」到「一个关键帧 + delay」的优化，本质是一次代码重构。今天你完全可以把代码 9-7 直接丢给 DeepSeek、通义灵码或 GitHub Copilot，问一句「这两个动画能合并吗？」，它通常几秒就能给出 animation-delay 方案。但请注意：先自己看出「运动规律一样、只差时间差」，你才有资格判断 AI 给的对不对。

  • 提示词示例：「下面两个 @keyframes 逻辑重复，请合并为一个，并用 animation-delay 实现错峰」。
  • AI 也擅长生成缓动曲线：描述「先快后慢再回弹」，它会给出合适的 cubic-bezier 参数。
  • 国产工具：文心快码、通义灵码均支持选中代码块后「解释 / 重构 / 优化」三种操作。
  • 职业提醒：AI 优化后的代码必须自己再跑一遍——视觉效果是 AI 唯一无法替你验证的东西。

本课小结

  • 做动画先分析构造：拆出几个元素、画出各自的时间线，再找它们之间的关系。
  • 呼吸灯：一个 bounce 关键帧（0%,100%{scale(1)} 50%{scale(0)}）+ animation-delay:1s，比两套关键帧更优雅。
  • 卡片翻转：先沿 x 轴、再沿 y 轴翻转，关键帧中必须带 perspective()，元素本身要 preserve-3d。
  • perspective 两种写法：父元素用属性（场景共用、关键帧干净），子元素用函数（自带透视、便于搬移）。
  • 排查顺序：名称是否一致 → 是否写了时长 → 是否写了 infinite → 3D 是否漏了 preserve-3d 与 perspective。
