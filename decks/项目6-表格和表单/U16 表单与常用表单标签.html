6.4

认识表单

没有表单，网页就只有「看」而没有「用」。

原理图解

表单的基本原理：一次数据的往返

教材原文：表单负责收集、发送和处理用户提供的数据，为 Web 应用提供更多的功能

① 用户输入并提交
用户在表单中输入想要提交的信息，这些信息会通过 HTTP 的 POST 方法或 GET 方法在服务器和客户端之间传递。
② 服务器接收并检查
服务器接收并处理，检查信息是否符合要求，例如检查用户名是否存在、密码是否符合要求等。
③ 分叉处理
检查通过 → 将数据存入数据库并反馈成功或失败；未通过 → 发送错误消息，要求用户重新输入。
④ 安全兜底
有时使用验证码防止机器人或恶意程序通过表单提交大量无效内容；还可借助 cookie 控制等手段防范 XSS 攻击。

代码与要点

form 标签：给数据划一个「围墙」

教材原文：form 标签有两个作用——限定表单范围、定义提交方式与后台处理程序

  • 作用一：限定表单的范围，定义一个特定区域容纳表单的相关控件；单击提交按钮时，该区域内的所有数据都将被提交给服务器。
  • 作用二：利用该标签的相关属性定义提交方式、指定后台处理程序。
  • name：指定表单名称，该名称同时作为表单的变量。
  • method：定义表单数据从客户端传送到服务器的方法，主要包括 GET 与 POST，默认使用 GET 方法。
  • action：指定处理表单的服务端程序；onsubmit：指定处理表单的脚本函数。
  • enctype：设置 MIME 类型，默认值为 application/x-www-form-urlencoded；上传文件时必须改为 multipart/form-data。
  • target：与 a 标签的 target 类似，规定在何处打开 action URL。
HTML form 语法
<form name="表单名称" method="提交方式" action="服务端程序">

对比辨析

GET 与 POST，别选错

教材问答要点 + 技巧：什么情况下必须用、什么时候建议用

GET 方法
  • 把表单内容附加到 URL 后面传送
  • 浏览器厂商对 URL 长度有限制，例如 IE 浏览器最大限制 2083 个字符，超出则提交按钮没有任何反应
  • 不具有保密性，不适合处理密码、银行卡卡号等保密内容
  • 不能传送非 ASCII 码的字符
  • 教材建议：执行搜索操作时，建议使用 GET 方法
POST 方法
  • 把用户填写的数据包含在表单的主体中传送给处理程序
  • 没有字符数和字符类型的限制，包含了 ISO 10646 中的所有字符
  • 所传送的数据不会显示在浏览器的地址栏中
  • 教材要求：当数据涉及保密内容时，必须使用 POST 方法
  • 教材建议：执行插入或更新数据库操作时，建议使用 POST 方法

代码与要点

文本框、密码框、文件域与隐藏域

四类最基础的 input 变体，语法只差一个 type

  • 文本框：<input type='text' name='文本框名称'>，输入内容以明文形式显示。
  • 密码框：<input type='password'>，用 * 或 ● 回显字符以保密。
  • 文件域：<input type='file' name='avatarPic'>，服务端通过 name 变量名获取文件数据。
  • 隐藏域：<input type='hidden' name='域名称' value='域值'>，数据以键值对形式提供：name 是键，value 是值。
  • 常见编程错误：name 属性值错误地使用了中文，或不符合标识符的定义；隐藏域未提供 name 和 value 属性。
  • HTML5 简化写法：readonly='readonly' 可简写为 readonly，disabled='disabled' 可简写为 disabled——这是布尔属性的简化写法。
HTML 文本框常用属性（教材表6-9）
<input type="text" name="文本框名称">

属性：
  maxlength   设置文本框中可以输入的最大字符数
  size        控制文本框的长度，单位是像素，默认值为 20 像素
  value       设置文本框的默认值
  placeholder 规定可描述输入字段预期值的简短提示信息
  readonly    规定该文本框为只读状态
  disabled    规定应该禁用该 input 标签

单选按钮与复选框

教材代码6-4、代码6-5：一组 gender，一组 astr

  • value：被选中后传递到服务端的变量值；checked：默认被选中，不指定则无默认选项。
  • 单选按钮的排他性通过相同的 name 实现。服务端读到的是 value（male/female），而不是显示文本「男」「女」。
  • 常见编程错误：单选按钮必须提供 type、name、value 三个属性，缺少任何一个都无法构成完整的单选按钮。
  • 复选框用法与单选按钮非常类似，区别在于单选按钮具有排他性，而复选框允许用户多选。
  • 常见编程错误：同一组复选框使用了不同的 name——同一组复选框必须使用相同的 name 属性值。

知识要点

label 标签：让用户点文字就能选中

教材问答：为什么用户必须精确选中文字前面的 ○ 或 □ 才能选中该选项？

  • 因为缺少 <label>。该标签专门用于 input 标签，用户只要单击 label，就可以实现对应 input 的聚焦。
  • 第一种：隐藏式（隐式绑定）——label 与 input 以父子嵌套关系形成隐式绑定：
    <label><input type='radio' name='gender'>男</label>
  • 第二种：指定式（显式绑定）——为 input 添加唯一的 id，在 label 中使用 for 属性实现显式绑定：
    <input id='lbm'><label for='lbm'>刘伯明</label>
  • 常见编程错误：使用指定式绑定时，for 属性值对应的是 input 的 id 属性值，而不是 name 属性值——这是初学者最常踩的坑。

select 标签：列表框与下拉列表是同一套标签

教材 6.5.3：下拉列表是「一次只能显示和选择一个选项」的特殊列表框

  • 列表框允许用户从选项列表中选择一项或几项，等效于单选按钮（单选时）或复选框（多选时）；选项较多时可节省很大的空间。
  • select 用于声明列表框，指定选项是否可多选、一次可显示几个选项；option 用于设置选项值 value 及是否为默认选项 selected。
  • 可选属性 multiple 实现多选效果：不添加时只能选择一个，添加时可选择多个。
  • 下拉列表不给 select 添加 size 和 multiple 属性即可——因为 size 属性值默认为 1，可理解为「当前列表框只显示一个选项的退化情况」。
  • 教材问答：select 的 name 属性值就是整个列表的变量名；提交时提交的是 option 的 value 属性值，后端根据 name 读取即可。

    <option value="fjl" selected="selected">费俊龙</option>
    <option value="nhs">聂海胜</option>
    <option value="lbm">刘伯明</option>
    <option value="jhp">景海鹏</option>
</select>

textarea 标签：多行文本域

教材 6.5.4：文本框只能单行显示，内容较多时改用文本域

  • 语法：<textarea name='文本域名' rows='行数' cols='列数'>…（此处输入默认文字）</textarea>。
  • rows 指定行数、cols 指定列数；也可使用 HTML5 新属性 placeholder 添加提示文字。
  • 默认文字 vs placeholder（教材问答）：如果仅添加提示文字，那么该变量的值仍为空；如果仅添加默认文字，那么变量的值就是用户添加的默认文字。
  • 一句话记忆：placeholder 仅起提示作用，不影响提交的值；而默认文字会影响提交给服务器的值，相当于对变量进行了初始化。
HTML 代码6-10（教材原文）
<form action="">
    <textarea name="comments" rows="5" cols="20" placeholder="有什么新鲜事想跟大家分享?"></textarea>
</form>
AI 前沿

AI 前沿：一句话生成整套表单，但校验规则得你来把关

表单是 AI 编码助手最常被调用的场景之一，也最容易「看起来对、实际错」

AI

对 DeepSeek、通义千问、文心一言 这类大模型说一句「做一个登录表单」，它能在几秒内输出 HTML 与 CSS。但教学与实践经验都表明：AI 生成的表单常常缺少 label 关联、缺少合适的 type、忽略 GET/POST 的选择，甚至把密码用 GET 提交。AI 负责「写得快」，你负责「写对、写稳、写安全」。

  • AI 辅助编码：通义灵码、文心快码、GitHub Copilot 可在 HBuilderX / VSCode 中根据注释实时补全表单结构。
  • AI 生成校验规则：让 AI 为学号、手机号、邮箱等字段生成正则表达式与提示文案，比手写高效得多。
  • AI 无障碍与合规审查：让 AI 逐项检查 label 是否绑定、必填项是否标注、保密字段是否走 POST。
  • 职业提醒：AI 不会替你承担数据泄露的后果——method 的选择、enctype 的设置、服务端校验的补全，始终由工程师负责。

本课小结

五句话收好，表单的地基就打稳了

  • 表单负责收集、发送和处理用户提供的数据；form 标签既限定范围，又定义提交方式与后台处理程序。
  • method 决定数据怎么走：GET 附在 URL 后、不保密、有长度限制、适合搜索；POST 放在表单主体中、无限制、不显示、保密内容必须用它。
  • input 靠 type 变形：text、password、file、hidden、radio、checkbox、submit、button、reset、image 共 10 种。
  • 单选靠同名 name 互斥，复选框同组必须同名；提交的是 value，不是你看到的文字。
  • label 有隐藏式（嵌套）与指定式（for + id）两种绑定；button 比 input 更能装，图片按钮直接放 img 即可。
