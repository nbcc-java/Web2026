10.1.1–10.1.2

传统的嵌入方式：object 与 embed

网页制作从嵌入文字、链接、简单图片，逐渐走向嵌入<strong>视频、音频、PDF、Canvas 动画</strong>等多媒体对象。HTML 提供了 <code>object</code>、<code>embed</code>、<code>video</code>、<code>audio</code> 等标签，<strong>但这些标签在使用时存在兼容性问题，需要额外注意。</strong>

代码与要点

object 标签：HTML 嵌入对象元素

教材原文：表示一个外部资源——图像、嵌套浏览上下文或插件要处理的资源

  • object 标签表示一个外部资源，可将其视为图像、嵌套的浏览上下文，或插件要处理的资源。
  • 涵盖范围：音频、视频、Java Applets 小程序、ActiveX 控件、PDF、Flash 等。
  • 设置初衷是取代 img 与 applet 标签，但由于漏洞及缺乏浏览器支持，这一初衷并未实现。
  • 可用于 Windows IE 3.0 及以上版本，或其他支持 ActiveX 控件的浏览器；主流浏览器用不同代码加载相同对象，需针对不同浏览器写不同语法。
  • 下方语法只对 IE 9 及以下低版本 IE 有效，对 IE 10/11 与非 IE 浏览器无效。
HTML index.html
<!-- 针对 IE 6～9 等低版本 IE 浏览器的语法 -->;
<object classid="clsid" codebase="url" width="w-value" height="h-value">
  <param name="movie" value="file_name">
  <param name="quality" value="high">
  <param name="wmode" value="opaque">
  …
</object>
代码示例

object 的兼容写法：嵌套 object + 条件注释

针对 IE 10/11 与非 IE 浏览器，需要在 object 标签中再嵌入一个 object 标签

HTML index.html
<!-- 针对 IE 10/11 浏览器和非 IE 浏览器的语法 -->;
<object classid="clsid" codebase="url" width="w_value" height="h_value">
  <param name="movie" value="file_name">
  …
  <!--[if !IE]>
  <object type="media_type" data="media_fileName" width="w_value" height="h_value">
  <![endif]-->;
  <param name="quality" value="high">
  <param name="wmode" value="opaque">
  <!--[if !IE]>
  </object>
  <![endif]-->;
</object>
原理：如果未显示 object 标签，则会执行位于 object 与 /object 之间的代码。在非 IE 浏览器中会执行条件注释 [if !IE] 内部的语句，从而实现对非 IE 浏览器的兼容。可借此嵌套多个 object（每个对应一个浏览器）。
常见的编程错误（教材原文）：Firefox 浏览器不支持 object 标签，把上述语法用在 Firefox 中是常见的编程错误。

知识要点

技术史：Flash 的兴与衰

教材原文，可作课程思政与技术史素材

  • Flash 作为嵌入网页的动画和多媒体应用，在网页发展历史中曾辉煌一时。
  • 衰落原因：对浏览器搜索引擎不友好，无法实现搜索引擎优化；且存在安全隐患。
  • 自 2021 年起，Adobe 已停止为 Flash 提供支持。
  • 在随后任何版本的 Google Chrome 浏览器中，Flash 内容（包括音频和视频）都无法再正常显示。
  • 目前尚有部分浏览器支持 Flash（如 360 浏览器和 QQ 浏览器），但并不保证以后还支持——新项目不要再依赖插件。
代码与要点

embed 标签：Netscape 插件路线的嵌入方式

与 object 一样可嵌入 Flash 动画、音频和视频，但适用浏览器不同

  • embed 与 object 一样，可用于在网页中嵌入 Flash 动画、音频和视频等多媒体内容。
  • 不同之处：embed 用于 Netscape Navigator 2.0 及其以后版本的浏览器，或其他支持 Netscape 插件的浏览器，包括 IE 与 Google Chrome。
  • Firefox 浏览器目前尚不支持 embed 标签——这是与 object 恰好相反的一个「坑」。
  • src 属性用于指定嵌入对象的文件路径；嵌入对象的格式可以是 MP3、MP4、SWF 等。
  • 教材注意：大多数现代浏览器已弃用并取消了对浏览器插件的支持，若希望网站能在普通用户浏览器中运行，建议尽量不使用 embed 标签。
HTML index.html
<!-- 基本语法 -->;
<embed src="file_url"></embed>

<!-- 示例：指定宽高与 MIME 类型 -->;
<embed src="assets/demo.swf" width="400" height="300" type="application/x-shockwave-flash"></embed>

任务 10-2｜嵌入视频

将教学项目源文件的 intro.mp4 显示在页面中（图 10-2），页面标题「课程宣传片-视频播放」

任务目标用一行 video 标签完成视频嵌入，并理解 src、controls、loop 的作用。
  1. 新建页面，标题写为「课程宣传片-视频播放」。
  2. 在需要的位置写入 video 标签。
  3. 必须设置引用的视频存放地址（src），可以是相对路径，也可以是网络路径。

  5. 用 width="80%" 让播放器随容器自适应宽度。
<!-- 代码 10-2 -->;
<video src="./assets/intro.mp4" controls loop width="80%"></video>
对比辨析

video 与 audio：几乎一样，只差一个属性

教材原文：audio 中不包含 poster 属性，其余属性用法相同

video 标签
  • 语法：<video src="file_url"></video>
  • 嵌入的音频格式包括 MP3、WAV、OGG、WebM 等（音频部分由编解码器决定）
  • 独有属性：poster（封面图）、width / height（播放器尺寸）
  • 有画面，因此需要占据一块区域
audio 标签
  • 语法：<audio src="file_url" controls></audio>
  • audio 标签中至少要包含 src 属性，它指定了音频文件的路径
  • 与 video 的差别：不包含 poster 属性，其余属性（controls、autoplay、loop、muted、preload）用法相同
  • 没有画面，通常只显示一条控件条

任务 10-3｜嵌入音频

将教学项目源文件的 intro.mp3 显示在页面中（图 10-3），页面标题「课程宣传音频」

任务目标掌握用 source 标签提供多种格式的兼容性写法，并给出不支持时的提示文字。
  1. 准备容器 .outer（800px 居中、背景 #FFE4C4）与标题 h2（红色 + text-shadow）。
  2. 写入 audio 标签，并加上 controls、autoplay、loop 三个属性。
  3. 不用 src 属性，而是在标签内部放两个 source 子标签。
  4. 分别给出 MP3 与 OGG 两种格式，尽可能确保用户浏览器能正常播放。
  5. 最后写一句「您的浏览器不支持audio 元素。」——不支持时用户会看到它。
  6. 启发问答：为什么不用 audio src="…" 的简单写法？因为用 source 可提供 MP3 与 OGG 两种格式，尽可能确保浏览器能播放，实现更加友好的兼容。
  7. 教材评价：不仅便于代码的调试和验证，还极大地提升了用户体验，是一种更加推荐的做法。使用兼容性写法满足不同浏览器的需求，是良好的编程习惯的体现。
/* 代码 10-3：CSS */
.outer{ margin:0 auto; background-color:#FFE4C4; width:800px; text-align:center; }
h2{ color:red; text-shadow:3px 4px #c3610863; }

<!-- 代码 10-3：HTML -->;
<div class="outer">
  <h2>课程宣传音频</h2>
  <audio controls="controls" autoplay="autoplay" loop="loop">
    <source src="./assets/intro.mp3" type="audio/mpeg">
    <source src="./assets/intro.ogg" type="audio/ogg">
    您的浏览器不支持audio 元素。
  </audio>
</div>

AI 前沿

AI 前沿：让 AI 帮你处理多媒体兼容与无障碍

多媒体是「兼容性 + 无障碍」问题最集中的地方，AI 恰好能兜底

AI

多媒体标签看似简单，却是最容易出错的一块：格式要转码、浏览器要兼容、移动端还常常禁止自动播放。借助 AI 工具（DeepSeek、通义千问、文心一言），你可以快速生成多格式 source 列表、字幕轨道与降级提示；借助 GitHub Copilot、通义灵码，则能在编辑器里补全整套播放器结构。但「能不能自动播放」「要不要加字幕」这类产品决策，仍然必须由你来做。

  • 提示词示例：「给这段 video 生成 MP4 + WebM 双格式 source，并加上中文字幕轨道与不支持时的降级提示」。
  • 无障碍提醒：视频应提供字幕与文字稿，音频应提供文字版本——这也是 1+X 考试与真实项目的共同要求。
  • 移动端经验：多数移动浏览器禁止带声音的自动播放，通常要配合 muted 使用。
  • 职业提醒：AI 生成的代码无法通过你的真机验证——在手机上跑一遍，永远是最后一道工序。

本课小结

  • 发展脉络：从插件时代的 object / embed，走向 HTML5 原生的 video / audio。
  • object：表示外部资源，初衷是取代 img 与 applet，但因漏洞与缺乏支持未能实现；Firefox 不支持。
  • embed：Netscape 插件路线，IE 与 Chrome 可用，Firefox 不支持；现代项目建议尽量不用。
  • video 常用属性：src、controls、autoplay、loop、muted、poster、preload、width、height、type。
  • audio 与 video 属性几乎相同，只是没有 poster；用 source 提供多格式 + 降级文字，是更推荐的兼容性写法。
