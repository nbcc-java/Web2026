5.1

盒子模型简介

CSS 假定所有 HTML 文档元素都生成了一个矩形元素框，人们形象地将其看作一个盒子。

知识要点

为什么要有盒子模型

教材原文改写：围绕这些盒子，产生了「盒子模型」（box model）概念

  • CSS 假定所有 HTML 文档元素都生成了一个描述其在布局中所占空间的矩形元素框。
  • 人们形象地把它看成一个盒子，也称「框」；有些书上也称框模型。
  • 一个网页由许多大大小小的盒子通过不同排列方式组合而成——布局的本质就是摆盒子。
  • body、html、div、p 等元素都会生成矩形盒子。
要点分解

盒子从内到外的四层结构

每层都形成一个矩形盒子，可形象区分为 content 盒、padding 盒、border 盒、margin 盒

① 元素内容 content
盒子的核心，显示文字、图片等主体内容。默认情况下 width、height 描述的就是它的尺寸。
② 内边距 padding
定义边框与元素内容之间的空白区域。绝大多数盒子默认为 0；ul、ol 等标签自带一定内边距。
③ 边框 border
包裹内边距和内容的边界，包含风格、宽度、颜色三个要素——下一单元的主角。
④ 外边距 margin
定义盒子与其他盒子之间的空白区域，也称「透明区域」，因为在外边距中无法显示背景。
知识要点

常见编程错误：width / height 到底量的是谁

教材原文提示，初学者几乎人人踩过

  • 在默认情况下，width 和 height 是用于描述 content 盒尺寸的。
  • 错误地把 width、height 当作整个盒子模型的宽高，是最常见的编程错误。
  • 正确的算法：元素实际占位 = content + padding×2 + border×2（外边距不算在元素尺寸内，但占据布局空间）。
  • 想要 width 直接等于最终看到的宽度，可以设置 box-sizing:border-box（MDN 推荐做法）。
  • 方向命名规律：padding、border、margin 都有上右下左 4 个方向，统一用 xxx-top、xxx-right、xxx-bottom、xxx-left 表示。

语法5-2 值复制原则

值复制原则在 margin、padding 等很多基于盒子模型的属性中都有广泛应用，务必牢记

定义值示例含义
定义 1 个值padding:5px;上、右、下、左 4 个方向的内边距都是 5px
定义 2 个值padding:5px 10px;上、下内边距均为 5px，左、右内边距均为 10px
定义 3 个值padding:5px 10px 6px;上内边距 5px，左、右内边距均为 10px，下内边距 6px
定义 4 个值padding:5px 10px 6px 7px;上、右、下、左内边距分别为 5px、10px、6px、7px
知识要点

记住顺序：永远从上开始，顺时针绕一圈

缺哪个方向，就找它对面的值来补

  • 四值：上 → 右 → 下 → 左，顺时针一圈，永不变。
  • 三值：缺省的是左，左复制右的值。
  • 二值：缺省的是下、左，下复制上、左复制右。
  • 一值：四个方向全部相同。
  • 简化示例：写 4 条 padding-方向:5px;，不如直接写一句 padding:5px;。

效果演示

效果演示｜一个盒子，四层同心的世界

以代码5-1 为例：content 100×50 → padding 5 → border 3 → margin 10/20

  • 四层由内向外依次出现：content → padding → border → margin。
  • content 盒始终保持 100×50，可见的就是 width、height 描述的那一块。
  • padding 盒被背景色覆盖——这是内边距的第二个重要特性。
  • margin 盒在最外层，不显示背景，只负责把别的盒子推开。
动手试试：把 padding 改成 5px 10px 6px 7px，然后对照值复制原则，说出四个方向各自是多少像素。
5.1.3

内边距特性

盒子的内边距定义了边框和元素内容之间的空白区域——它有两个必须掌握的特性。

对比辨析

内边距的两个特性

一个改变尺寸，一个决定背景画到哪儿

特性 1：padding 影响元素尺寸
  • 默认情况下 width 指的是 content 盒宽度
  • 因此增加 padding 会影响整个元素的尺寸
  • 任务5-2 实例：width 150px + padding 左右各 10px = 实际 170px
  • 算尺寸时千万不要漏了这一层
特性 2：padding 可以显示背景
  • 背景不仅对 content 盒有效，还对 padding 盒有效
  • 给盒子添加 padding 时，padding 会撑开盒子，背景效果随之延伸
  • 反之，margin 区域无法显示背景
  • 这一点是后面学习 background-clip 的伏笔
代码与要点

算一算：150px 的盒子为什么变成 170px

任务5-2 的核心计算（图5-6）

  • 第 008 行设置盒子宽度 width:150px——这是 content 盒的宽度。
  • 第 014 行设置 padding:5px 10px：按值复制原则，上下 5px、左右 10px。
  • 用户看到的矩形宽度 = 150 + 10 + 10 = 170px。
  • 同理，高度方向也要把 padding 的 5px×2 计算进去。
  • 验证方式：打开开发者工具的盒子模型面板，逐层核对数字。
CSS 代码5-2 中的关键声明
.box {
    width: 150px;              /* #008 content 盒宽度 */
    display: flex;
    justify-content:center;
    align-items:center;
    background-color: #F6F9FC;
    padding:5px 10px;           /* #014 上下 5px、左右 10px */
    margin-bottom:10px;
    border-radius: 5px;}
/* 用户看到的宽度 = 150 + 10 + 10 = 170px */

知识要点

易错与提示

写 padding 之前，先在脑子里问这三个问题

  • padding 不能取负值（与之相对，后面要学的 margin 可以取负值）。
  • 绝大多数盒子默认 padding 为 0，但 <ul>、<ol> 等标签自带一定的内边距，做列表前常先清零。
  • 用百分比设置 padding 时，计算基准是父元素的宽度，包括上下方向也用宽度算——这是 CSS 的经典规定。
  • 想让 width 直接代表最终看到的宽度，可设置 box-sizing:border-box（详见 MDN）。
AI 前沿

AI 前沿：设计稿里的留白，正在被自动算出来

padding / margin 的提取，是 AI 辅助前端最成熟的场景之一

AI

设计师给的稿子里没有写 padding，只有「看起来舒服」的视觉间距。过去前端要用开发者工具一个个量；现在多模态模型可以直接读取设计稿，反推出每个盒子的内边距、外边距与层级关系，并生成带注释的 CSS。

  • 设计稿转代码：通义灵码、文心快码、GitHub Copilot 等已支持根据描述生成带合理 padding 的卡片布局。
  • 视觉还原校对：让 DeepSeek、通义千问核对「这张卡片的 content 宽度与 padding 值」，可快速发现 8px / 10px 这类差量。
  • 现代 CSS 的替代方案：MDN 推荐的 gap 属性配合 flex / grid 布局，可以减少大量手写的 margin 微调。
  • 提醒：AI 给出的留白往往是「看起来差不多」，是否符合栅格与倍率规范，仍要你来把关。

本课小结

  • 盒子模型从内到外四层：content → padding → border → margin，每层都是一个矩形盒子。
  • 默认情况下 width、height 描述的是 content 盒的尺寸，这是个高频编程错误。
  • 值复制原则：上右下左顺时针，缺哪个方向就找对面的值来补。
  • 内边距两特性：影响元素尺寸、背景可延伸到 padding 区域。
  • 任务 5-1、5-2 分别训练了「用开发者工具核对盒子」与「用 padding 做功能项卡片」两项基本功。
